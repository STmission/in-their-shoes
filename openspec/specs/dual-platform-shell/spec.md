# dual-platform-shell Specification

## Purpose

双端外壳让同一套游戏代码同时发布为 H5 网页与微信小程序，保证两端玩家获得一致的核心体验，同时容忍各端平台能力差异。

## Requirements

### Requirement: 一套代码双端构建

工程 SHALL 能通过构建命令分别产出 H5 静态站点与微信小程序包，游戏逻辑与题库 MUST 为两端共享的同一实现，禁止为单端复制业务代码。

#### Scenario: H5 构建

- **WHEN** 执行 H5 构建命令
- **THEN** 系统 MUST 产出可直接部署的静态文件，浏览器打开即可完整游玩

#### Scenario: 微信小程序构建

- **WHEN** 执行微信小程序构建命令
- **THEN** 系统 MUST 产出可被微信开发者工具导入的小程序包

### Requirement: 页面流

应用 SHALL 包含三个页面：首页（标题、阵营选择、开始按钮）、对局页（题目、选项、进度、即时反馈）、结果页（共情指数、称号、再来一局、分享）。移动端优先，竖屏单手操作。

#### Scenario: 完整游玩路径

- **WHEN** 玩家从首页进入
- **THEN** 玩家 MUST 能依次完成"选阵营 → 答完全部题目 → 查看结果 → 再来一局"的闭环，中途无死路

### Requirement: 平台差异降级

平台专属能力（如小程序分享卡片、H5 链接分享）SHALL 按平台条件实现，能力不可用时 MUST 静默降级而非报错。

#### Scenario: 分享降级

- **WHEN** 玩家在 H5 端点击分享且系统剪贴板/Web Share API 可用
- **THEN** 系统 MUST 复制或调起分享；不可用时 MUST 提示玩家手动复制链接
